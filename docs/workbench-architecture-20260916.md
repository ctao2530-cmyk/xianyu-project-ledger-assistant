# 个人版工作台架构优化 · 2026-09-16

## 本轮范围与现状

以《循营三轮迭代重构方案》为参考，本轮落地当前个人版的工作台与代码边界调整；附件中的代理分工、团队上线与数据库迁移属于规划材料，不作为独立操作授权。没有实施完整团队版，也未推送 GitHub。

实施前当前工作树有大量既有修改；逐文件保留，未重置。此次涉及的原文件备份保存在本机临时目录 `xunying-architecture-20260916/before-source`。基线类型检查与相关 41 项前端测试通过；未将招聘展示副本的测试作为当前测试结果。

知识复用：复核既有“账本写入采用修订号与请求 ID 双重保护”决策。相同点是单实例 SQLite 与受保护的真实业务写入；不同点是本轮重点为只读展示和模块边界。保留修订与幂等，不采用团队共享、微服务或新权威库；如果界面更改引发无确认写入，即为失败信号。

## 已实现

1. **共享业务计算**：将收支记录生成、类型与相关日期处理移入 `src/data/operatingRecords.ts`。工作台不再加载收支页面来获取计算函数，原页面保留 `buildRecords` 再导出以兼容既有调用。金额、退款与待回款口径保持原逻辑。
2. **待办加载与展示分离**：只读客户/需求加载移到 `src/components/workbench/useWorkbenchActions.ts`，保留并发上限、事件刷新、失败提示与卸载保护；客户集合变动时清空上一轮结果。
3. **行动优先的信息结构**：复用现有待办工作台作为首页首屏；原统计内容收进“经营概览与统计”。`BusinessOverviewDisclosure` 仅在展开时挂载图表，收起时卸载。没有删除历史功能或新增主题覆盖层。
4. **真实项目排序**：复用 `BusinessProject.updated_at`，账本读接口及保存响应输出 `updatedAt`；忽略客户端伪造值，不保存该派生元数据。项目排序按时间降序、同时间按 ID 稳定排序，缺失/无效时间排后。时间表示项目数据库行资料更新，不能冒充客户原始消息时间或所有关联业务活动时间；未新增数据库列。
5. **真实环境身份边界**：新空账本不再预填人名和套餐；顶栏改为“本地工作空间”，空名称回退为“经营者”。已有用户自行保存的名称保持不变，不批量修改历史设置。

依赖方向：

```text
App → 工作台 / 收支页面
工作台 → useWorkbenchActions → 本地 API
工作台、收支页面 → operatingRecords → 账本数据与统一计算
项目列表 → projectOrdering ← 账本 API 的服务端更新时间
```
