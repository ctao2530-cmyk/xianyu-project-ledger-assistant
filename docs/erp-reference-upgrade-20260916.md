## 已实现

- 收支增加“收支明细 / 回款跟进”视图，记住本会话选择；当前待回款摘要可直接打开跟进看板。
- 看板分为未到期/今日到期、逾期 1–30 天、31–60 天、61 天以上、未约定日期和计划待核对。图条使用全部接单待收余额作分母，固定容器不会随金额增长。
- 每组可筛选明细；搜索客户/项目；首批最多 10 项，按需再显示；查看项目直达该项目合同回款分区。
- 删除侧栏重复且仅显示前五项的回款提醒列表；保留快速记录收入、支出及原有收支轨道。
- 项目原合同和追加订单下均可展开收款节点；显示约定日期、实际到账日期（已到账记录）、金额和状态。针对具体节点打开原有确认表单，不直接写入。

## 账龄计算边界

独立纯函数位于 `src/features/receivables/model.ts`，UI 位于相邻组件。没有新增 API 或数据库迁移。

1. 只统计接单项目，按稳定 projectId/customerId 关联。已终止项目有余额仍保留，并明确标记。
2. 余额复用 `getProjectFinancials` 的已收、退款与结算规则，不修改账本定义；使用分为单位汇总，避免 0.1 + 0.2 导致误判。
3. 每个有效未收节点按北京时间约定到期日分组；今日到期不算逾期。未覆盖余额归入未约定日期。绝不借用交付日期推断逾期。
4. 未收节点合计超过余额，或节点金额/客户归属异常，整个项目余额归入计划待核对一次；不强行分摊或重复计算。该分组只提供原项目入口。
5. 同项目可跨组，分组项目数不能直接相加作为独立项目总数；金额合计等于接单待收余额。历史月份和明细筛选不改变当前看板余额。
6. 每分钟及页面重新可见时只更新本地北京日期，无远程轮询。浏览和筛选不触发写入；到账与计划仍走既有表单、版本及请求保护。
