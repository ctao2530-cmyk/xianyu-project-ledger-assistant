# 循营 UI 设计重构

## 设计目标

围绕一人经营者的客户接单、需求确认、项目交付和回款工作。改造呈现，不修改业务数据定义、授权、确认流程和既有路由。默认采用浅色中性工作台、蓝色操作与紫色品牌标记；不新增营销首页或团队功能。

## 视觉规范

- 画布 `#F4F6F9`，面板 `#FFFFFF`，正文 `#202B3D`，辅助文字 `#65738A`，边框 `#E1E6EE`，主操作 `#2563EB`；品牌标志保持紫色。
- 中文系统字体优先使用苹方，标题 19–24px、正文 14px、辅助信息 12px；金额使用等宽数字，不用装饰字体影响账本阅读。
- 桌面侧栏 224px、顶栏 72px；手机顶栏 64px、抽屉导航。主间距以 4/8/12/16/24 为单位。
- 面板圆角 12px，控件 8px；减少大阴影、渐变、无业务价值的图片。保留真实品牌与客户图片原件。
- 主操作实色蓝，选择态浅蓝，普通操作白底边框；成功、异常和风险沿用语义颜色。

## 页面结构

1. 工作台：以真实待办为主体，右侧辅助信息；历史经营摘要继续按需展开。
2. 客户：名单与会话连续分栏，资料按需打开；保持原有只读沟通、消息搜索、图片和授权入口。
3. 项目：统一列表、筛选、详情分区和编辑页；客户、来源、需求、任务、验收和回款关系不变。
4. 收支：历史明细与当前回款跟进分开；账龄卡片只负责筛选，记录页使用统一表格密度。
5. 商品、分析、设置：沿用相同容器、文本、控件、状态与响应式规范，保留已有功能。

## 样式架构

`src/design/tokens.css` 是颜色、字体、圆角和布局尺寸入口；`src/design/workspace.css` 是当前组件适配与布局主题。生产和隔离预览同步加载。AppShell 使用 `studio-workspace`；停止加载 `august-24-theme.css`，保留历史文件以便追溯，不删除用户既有资产。

现有页面功能样式继续保留，逐步统一到当前主题。此轮不宣称所有历史 CSS 都已删除；也不通过全局缩放、滤镜或整体着色改变页面。

## 验收要求

在合成数据预览中验证桌面与手机：主导航、搜索、客户切换/资料、项目列表与详情、回款、弹窗、设置和分析；检查布局溢出、按钮可操作性、键盘焦点、控制台错误和减少动效设置。构建成功不能替代浏览器验收。

## 验证结果

- TypeScript 检查通过；生产构建通过。136 项回归测试通过：108 项交互与源码边界测试、24 项业务模型测试、4 项 Sites 测试。
- ego lite 使用合成数据，检查 1440×1000 和 390×844 的工作台、项目、客户、收支、经营分析、设置：页面无横向溢出，未捕获 window error 或 unhandled rejection。
- 验证项目列表进入详情和编辑、客户资料展开、手机名单与会话切换、回款视图切换，以及全局搜索打开、Escape 关闭和焦点返回。没有提交真实业务表单。
- 修复手机名单与会话同时显示、待办按钮换行、项目操作和编辑标签文字过小。
- 截图目录：design-qa-evidence/2026-09-16-ui/。截图等待页面过渡结束后保存，均为合成数据。
- 浏览器前期高负载超时，已在原任务空间恢复，没有关闭其他任务。
- 本地 8877 健康接口返回 200，页面资源与构建匹配。没有更换端口或重启后端。
- 部分历史页面样式继续保留；构建仍报告现有大文件体积警告。本轮没有清理全部旧 CSS 或进行性能拆包。
- 没有 Git 提交或推送、真实业务写入、客户通信、模型付费调用或平台采集验收。
