# 循营模块化重构 · 执行记录

本轮授权：全面升级当前个人经营工作台。保留既有界面风格、路由、账本规则、授权边界；不引入团队权限、换库或远程发布。

## 分阶段实施

1. 工作台：只读聚合查询、稳定分页、准确时间语义、前端加载取消与明确状态。
2. 业务基础：共享北京时间规则、独立待办领域计算、兼容原导入路径与行为。
3. 恢复和诊断：真实导出范围、独立本地备份与恢复校验、无外部副作用的就绪检查。
4. AI 与交付：受控输出与用量反馈、正式验收记录的版本和证据边界、隔离验证。
5. 质量：前后端统一检查与 CI、合成浏览器验收、交付状态与待批准项。

## 约束

- 不清理或覆盖原有未提交修改；已保存本轮源码基线。
- 不升级依赖、不读取或导出真实客户内容、不调用付费模型。
- 真实数据库迁移或恢复、Git 提交/推送与部署需明确批准；先完成可审阅实现和隔离验证。
- 历史财务规则、GPT 授权、需求版本、图片原件与关系确认必须保持。

## 验收

领域行为测试、API 权限与分页测试、迁移及恢复合成测试、类型/构建、桌面和窄屏交互。每一结果按本地源码、隔离验证、当前运行版本分别记录。

## 本轮已实现

- 新增 `features/workbench`、`features/delivery`、`features/maintenance` 与共享日期层。原收支日期入口保留再导出；金额和退款规则未改。
- `/api/workbench/actions` 为 SQLite 只读聚合，分页上限 200。每次页面请求使用一个只读事务、两条查询，不随客户数逐个发送请求；不返回客户原文、图片或提案令牌。分页为当前查询快照，跨页实时更新时可刷新重读，不宣称冻结历史快照。
- 原会话列表接口改为一条查询，包含最近消息和商品关联；同消息时间以数字 ID 决定顺序。旧 API 响应兼容。
- 待办领域计算独立：已逾期、临近交付、待回款分开；项目终止后不再提示交付，但保留结算事实。更新排序只使用更新时间，另提供交付日期排序。请求可取消，部分结果与失败显式提示。
- 客户验收使用既有 `LedgerMutationRequest` 追加独立操作记录，绑定项目、客户、正式需求版本与内容哈希。记录前核验版本和修订号，显式确认，幂等重放；旧版本记录保留。只记录操作者转录的结论，不是客户身份认证或在线签名，不把整个版本结论冒充每条验收项单独通过。不修改项目交付状态或金额。
- 离线本地备份工具包含 SQLite 一致性副本和白名单文件目录：原始客户图片、预览、需求附件、需求导出、项目附件；校验文件清单、SHA-256、数据库完整性和外键。拒绝符号链接、覆盖目标和无停写确认的打包。只恢复到新离线目录，不启动服务、不覆盖当前工作区。
- 设置页明确账本 JSON 的覆盖范围；增加数据库就绪状态和 OpenAI 持续分析当日用量。诊断仅查本机数据，不发起平台/模型检查。
- OpenAI 持续分析默认每天最多创建 100 次分析尝试，按北京时间重置；单次输出上限 12000 tokens，可在环境配置调整。失败尝试计入保守限额，未知或失败请求可能产生费用，因此不宣称这是费用硬上限。提供方用量保存在已完成产物的差异元数据中；缺失数据展示未知。
- 新增后端 CI，`check:all` 连接前后端检查。修复测试隔离守卫对合法临时 SQLite `file:` URI 的误判，仍拒绝项目数据库与远程 SQLite URI。
